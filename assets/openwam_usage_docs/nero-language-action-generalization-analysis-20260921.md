**Nero 三任务 Rot6D 微调：语言遵循、场景迁移与动作特化分析（2026-09-21）**

本报告由三个并行 agent 分别审计动作/部署、语言/数据和一手研究，再交叉核对形成。范围为现有源码、实际保存配置、项目维护文档、既有评测产物，以及用户描述的真机现象；本次没有重新运行模型或真机实验。用户补充：最新权重可能更明显过拟合；环境 OOD 主要指改变场景。真机现象尚无逐次日志、成功率样本量或配对视频，因此以下区分代码事实、机制假说与待测结论。

目前最有解释力的工作假说是：模型学会了对当前机器人可用的闭环操作，在场景变化时仍能执行熟悉技能；但语言对目标、任务阶段和动作顺序的约束较弱，部分新指令会被接续为训练中常见的动作。它比“语言没有作用”或“视觉泛化而 action head 过拟合”的定论更符合现有证据。

**实际实验身份与数据事实**

| 模型 | 归档与最终 checkpoint | Global batch | 最终训练量 |
|---|---|---:|---:|
| 相对 EEF | step4000 / step8025 | 8 GPU × 64 = 512 | 5 epochs，约 4.11M 窗口曝光 |
| 绝对 EEF | step4000 / step16045 | 4 GPU × 64 = 256 | 5 epochs，约 4.11M 窗口曝光 |

相对模型实际来源是八卡独立训练，不能拿工作区历史四卡 resume 配方替代其身份。[相对模型说明](../../models/nero_relative_8gpu_b64_20260919/README.md)、[相对保存配置](../../models/nero_relative_8gpu_b64_20260919/step_8025/config.yaml)、[绝对保存配置](../../outputs/nero_absolute_4gpu/2026-09-20_02-15-44/config.yaml)、[绝对配方](../../configs/train_nero_absolute_4gpu.yaml)共同确认：均由 foundation 微调，LR=1e-4、5 epochs、GAS=1。

两个最终点近似等数据曝光，但绝对模型的优化器更新次数约两倍。两个 step4000 更不等价：相对约 2.49 epochs，绝对约 1.25 epochs。等曝光近似对应 relative4000 与 absolute8000，但即便如此仍有 batch/优化轨迹混淆；严格比较动作表示需要同 global batch、同数据与训练计划的对照。

数据共有 408 episodes、834400 frames、821344 个高度重叠滑窗。月饼/锤子/插头为 204/102/102 episodes，窗口占比约 59.6%/24.5%/15.9%；按窗口自然采样，未做任务均衡，全部 episode 参与训练。821344 个滑窗不代表同样数量的独立语义决策。[数据审计](../../outputs/nero_multitask_data/audit.json)、[数据设计](nero-multitask-finetuning-design.md)。

每个任务只有一段固定英文全流程 prompt，没有逐阶段语言标签。月饼最后的 `[box destination]` 占位符仍保留；锤子 prompt 明确包含右手向左手 transfer。占位符是目的地语言监督缺失的一例，不能单独解释所有泛化问题。[reader](../../openwam/dataloader/nero_multitask.py)、[数据审计](../../outputs/nero_multitask_data/audit.json)。

实际模型为 Wan2.2-TI2V-5B + ActionDiT 的 dual_system / joint_self_attn，冻结 UMT5 和 VAE，没有使用可选 Qwen VLM。当前绝对 EEF state 编码为一个 token，追加在文本 context 中，供条件 attention 使用；相对动作模型也输入绝对 state。冻结文本编码器不保证下游 grounding 保持不变，视频 DiT 与动作模块仍在训练。[保存配置](../../models/nero_relative_8gpu_b64_20260919/step_8025/config.yaml)、[条件编码代码](../../openwam/model/architectures/base.py)。

**现象 1：绝对空间似乎更成功**

这一观察合理，但目前只支持“现有绝对模型及部署组合表现更好”。除 batch/更新次数混淆外，还存在以下机制候选：固定机器人与相似工作区域下，绝对输出可直接拟合熟悉的目标位姿；相对输出还要结合当前状态生成对应差值。相对动作在解码时显式使用 anchor，因此 state 误差、同步误差可能影响输出；这里只是待测敏感性，未发现相应部署 bug。

当前相对定义是：

```text
Δp[k] = p[t+k] − p[t]              # 仍在 body axes 中
ΔR[k] = R[t].T @ R[t+k]            # 再编码为 Rot6D
gripper[k] = absolute_width[t+k]
k = 1..32
```

全部预测相对于同一个 chunk 起始状态；部署使用该请求保存的 anchor 还原一次。它不是逐帧 delta 积分，也不是所有维度都在末端局部坐标系中。因此“relative 在 chunk 内必然逐步累积漂移”不适用于这里。[表示代码](../../openwam/dataloader/utils/nero.py)、[部署 engine](../../openwam/deploy/engine.py)。

Rot6D 表示方式与 absolute/relative 是两个不同设计轴；两组都用 Rot6D，本次没有单独检验其收益。动作空间系统研究也表明表示方式和 chunk/执行长度共同影响结果，不能从单个配方推出绝对或相对的普适优势。[Demystifying Action Space Design](https://arxiv.org/abs/2602.23408)。

部署比较还应记录实际 denoise steps、执行步数与延迟。项目迁移基线使用 10 步去噪，而当前 `configs/deploy_nero.yaml` 默认 4 步；既有文档明确两者输出不同，速度收益没有被证明等价于成功率。不能由文件默认值断言用户两次测试一定使用不同参数，应从各次服务日志核对。[性能文档](nero-inference-performance.md)、[当前部署配置](../../configs/deploy_nero.yaml)。

**现象 2：月饼场景与 prompt 下仍抓锤子**

这是物体类别约束不足的线索，但实验本身没有隔离语言的因果作用。月饼和锤子任务都包含“从传送带抓物体”；如果只摆一个可抓物，抓取阶段可能符合多种行为策略。更有区分度的是后续：放入盒子、双手交接、还是放在红框？也可能模型把锤子当成通用可抓物，沿用月饼流程，而不是直接选择锤子任务。

已有真实权重审计提供了重要反证：relative8025 在固定 observation/state/seed 下，锤子 A → 插头 B → 锤子 A，prompt 原文和不同 embedding 均进入模型；640 个动作元素中 596 个改变，回到 A 后逐元素复现。这证明语言参与计算，但不证明输出变化在语义上正确。该结果仅是一个锚点的离线链路测试，不能覆盖本次全部真机运行。[prompt 审计](nero-prompt-switch-audit-20260920.md)、[原始结果](../../outputs/nero_prompt_switch_validation/relative_8025/result.json)。

更准确的怀疑是：画面和 state 对任务/阶段的预测过于容易，语言没有成为决定动作所必需的变量。仅三个固定长 prompt，即使被当作三个任务标签也能降低训练损失，而不必学会任意对象、目的地和步骤组合。类似的视觉捷径已在 generalist robot policies 中被直接研究。[Shortcut Learning in Generalist Robot Policies](https://arxiv.org/abs/2508.06426)。

实验日志还应核对实际服务端 prompt；项目明确区分推理面板 `inference.set_task` 与录制标签 `record.set_task`，后者不改变推理指令。这是排除接口混淆的核对项，并非认定用户用错入口。

**现象 3：换场景仍会做月饼，但抓鸭后出现锤子的 transfer**

需要分开四种能力：场景变化下保持执行；识别新目标；把语言绑定到正确目标/目的地；按新指令组合动作。前一种成功不能自动证明后几种。尤其三路相机中，即便头部画面变化很大，腕部局部视野、物体相对布局和机器人姿态仍可能接近训练数据。用户当前信息支持“场景变化下任务迁移”，不足以认定视觉、几何、state 和动力学都完全 OOD。

鸭子例子最值得研究的是分支点：抓起后的状态可能类似锤子训练中的“右手持物”阶段，于是后续接续为左手接物。一个可检验的工作假说是“语言足以影响部分目标选择，但不够约束整个行为序列”。也可能是物体未正确识别、目的地角色混淆、没有学过直接放碗的组合，或相似状态对应不同阶段却缺少辨别信号。

因此不宜直接定位为 action head 过拟合：当前视频/动作双向交互，错误可能发生在视觉 grounding、条件融合或动作生成的任一部分。“动作落在训练分布”本身也不是错误，复用技能本来有价值；错误是该技能在当前目标下被选择或排序得不合适。

ALT 研究在小数据 diffusion policy 中发现 OOD 图像仍可触发近似训练轨迹，为“熟悉动作续接”提供相关机制候选；它不证明当前大规模预训练 WAM 是查表器。[Demystifying Robot Diffusion Policies / ALT](https://stanfordmsl.github.io/alt/)。

如果“环境+任务都新时更听 prompt”经重复实验成立，可以假设熟悉视觉线索变弱后，语言对行为选择的相对影响增加。但这不是已观察到的内部路由机制；没有多目标、对照指令时，抓起某个物体也可能只是通用抓取。

**现象 4：base model 配混合任务归一化后难以完成任务**

该结果说明 base + 当前输入输出映射不能直接完成当前任务；它与“微调适配构型”一致，却不能说明微调只做构型适配。微调也可能改变相机特征利用、语言 grounding、任务阶段映射、动作时序和运动先验。

归一化改变输入坐标与输出数值的物理解释。Nero 使用 min-max；foundation 保存配置中多项机器人数据使用 quantile。更换 stats 并非仅仅更换单位，也未必保留 base 原有的控制语义。若进一步把按绝对动作语义训练的输出用相对动作 stats 和解码解释，试验还混入了动作定义不匹配。[foundation 配置](../../models/OpenWAM-Alpha-Pretrain-Foundation-Model/config.yaml)、[Nero 配置](../../configs/dataloader/nero_multitask.yaml)、[Normalizer](../../openwam/dataloader/transforms/normalize.py)。

应将“base + Nero adapter”明确作为整体零样本基线，记录 action mode、state/action stats、槽位、frame、TCP/flange、夹爪单位与实际解码。本次没有找到足以重建用户该次 base 实验全部参数的记录，因此不能断言它发生了某种具体错配。即便保证这些接口正确，base 不会当前构型也不等于没有可迁移语义知识。

若要检验收益来源，可在固定数据/全局 batch 的小规模实验中比较：仅训练输入输出适配模块、仅动作相关模块、当前联合微调；辅以独立任务/反事实指令集。若前者接近全部收益，才更支持以构型适配为主。该建议是新的实验设计，本次未执行。

**现象 5：黄色比鸭子类别更有吸引力**

如果黄鸭确实在场，却抓黄碗，这支持对象类别或目标/容器角色绑定不足的怀疑，但需控制位置、大小、可达性和可抓性。用户第一例尚未明确黄鸭是否在场，需先确认目标存在。完整 prompt 同时出现 duck 和 bowl，抓碗还可能是把被操作对象与目的地角色混淆。

“只有蓝鸭和黄色其他物体，却要求黄鸭”中，满足描述的对象不存在。它检验的是冲突属性/缺失目标处理；选择部分匹配目标不能单独证明不认识 duck。如果随 yellow/blue 指令改变所选颜色，这甚至说明模型使用了部分语言信息。应将这组与目标确实存在的试验分别计分。

当前两组训练都关闭 color jitter，这允许固定颜色相关性被保留，但不是颜色偏好的因果证明。也不宜直接用任意 hue jitter 修复，因为图像颜色改变而语言不变会制造错误标签。属性绑定困难在视觉语言模型中有相关研究，但 CLIP 的证据不能直接当作 Wan 的诊断。[Does CLIP Bind Concepts?](https://aclanthology.org/2024.findings-eacl.101/)。

**如何检验“最新权重更过拟合”**

已有三条训练 episode、176 窗口开环结果：relative4000 → relative8025，左右位置均值误差由约 4.70/2.77 mm 降至 1.94/1.37 mm；左右旋转误差由约 1.35/0.75° 降至 0.62/0.36°。这是训练轨迹拟合改善，与 OOD 指令遵循下降完全可能同时发生。[模型评测说明](../../models/nero_relative_8gpu_b64_20260919/README.md)。

现有评测明确是训练人口开环拟合，并无保留验证 episode。不能用训练 loss 单独证明或否定过拟合。若独立测试显示 ID 成功率维持/上升，而反事实指令成功率降低、错误 transfer 增多，才有更直接的“后期行为特化增强”证据。要进一步称为预训练语义的灾难性遗忘，还需证明微调前或早期原本具备相应能力且后来退化。

VLM2VLA 等研究确实讨论机器人微调损伤语义能力，但当前系统并非其 VLM 架构，文本编码器又被冻结，因此不能直接套用其病因。更适合先测语义是否能控制动作，而不是先假定编码器忘记了对象。[Actions as Language](https://arxiv.org/abs/2509.22195)。

**优先实验：使用现有四份权重，不先扩大训练规模**

| 顺序 | 对照设计 | 分开记录的指标 | 能区分的问题 |
|---|---|---|---|
| 1 | 同一多目标场景、相同 observation/state，只换可执行且互斥的指令；离线固定相同 noise，再用多个 seeds 测随机变化基线 | 平移距离、SO(3)测地角、夹爪；目标与目的地是否随指令改变 | 数值敏感与真正语义遵循 |
| 2 | 鸭子已被同一只手抓起的匹配状态，分别要求直接放碗、先交另一只手再放碗；先离线快照，再物理一致地复现实验 | 抓取率、直接放置率、不必要 transfer 率、最终成功率 | 初始选取正确与后续序列受控是否分离 |
| 3 | 黄鸭、蓝鸭、黄碗、蓝碗同时在场，四种目标指令交叉，循环交换位置 | 颜色正确率、类别正确率、完整目标正确率 | 颜色偏好、属性绑定、位置/可达性捷径 |
| 4 | 背景/工作台变化与任务指令交叉，保持候选物体和几何位置；新旧场景都测多个可执行任务 | 正确目标与后续动作、各场景差值 | 场景代理任务与场景鲁棒性 |
| 5 | 四权重复用同一组初始条件，随机/交错测试顺序，每条件先做约10–20次配对试验 | ID/OOD分项成功次数与总次数、错误类型、区间估计 | 后期特化趋势，减少场景漂移混淆 |

10–20 次仅作为发现大效应的起点，不保证小差异显著；不要只报百分比。场景/任务/OOD轴分开记录，避免一次改变所有因素后无法归因。先在任务已有且可执行的分支上检验语言，再检验未见动作组合；不会一种新技能不等于完全忽略语言。

短指令可作为诊断，但训练只有长整段 prompt，短指令本身也是语言分布变化。应同时测试含义一致的长/短版本。空指令、打乱文本作为辅助对照，不是完整语言能力的唯一指标。当前 Wan 路径没有可直接使用的 unconditional context，不要把提高 CFG 当成现成修复；代码要求相应 CFG 条件支持。[模型实现](../../openwam/model/architectures/base.py)。

另一个低成本数据探针是仅用 state 预测 task/阶段，并按 episode 分割。高准确率说明数据存在可用捷径，不证明原模型使用了它。黑图、零 state 或不物理一致的图像/state交换会引入强 OOD；此类离线消融不能直接定量解释各模态的重要性。新验证集应按 episode，最好按场景/采集批次划分，不能随机拆相邻滑窗。

**如果上述假说被支持，训练数据该如何改变**

最高优先级是补充“同一或近似场景、同样候选物体和起始状态，不同语言必须产生不同对象选择、目的地或后续动作”的演示。尤其采集右手持物后直接放置与交接两种分支，打破持物姿态对 transfer 的唯一预测关系。补充颜色×类别×位置交叉，并给成功结束、目标缺失等行为明确监督。

仅增加三条 prompt 的同义改写，或每个任务分别采更多相似演示，未必让语言成为必要条件。反事实数据必须与动作一致：不能把 transfer 演示随意改标成直接放碗。CAST 的相似观察下任务多样性分析支持这一方向，其结果不是对当前双臂系统的效果保证。[CAST](https://arxiv.org/abs/2508.13446)。

有阶段标签时可补充子任务监督或检验高层任务选择与低层执行的分离；仅加 planner 不能保证当前低层遵从子任务。模块冻结、降低学习率、预训练数据混合等可作为后续受控消融，先用反事实测试确认瓶颈；它们不能替代缺失的语义分支数据。

报告中的因果解释均保留为待测假说。最应优先回答的问题是：在视觉与 state 基本相同、且确实存在不同可执行选择时，语言能否改变目标以及抓取后的下一步；这种能力是否在中间到最终权重之间下降。
